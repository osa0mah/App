# أثر القرآن

تطبيق عربي أولي للقرآن والتعلم على Android وiOS والويب، باستخدام Expo SDK 58 وReact Native وTypeScript.

## التطوير

```sh
cd /workspace/App
npm ci
npm start
```

التسميع الأصلي يستخدم `expo-speech-recognition`، ولذلك يحتاج **development build** يتضمن هذه الوحدة، ولا يعمل في Expo Go. استخدم `npx expo run:android` مع Android SDK أو `npx expo run:ios` على macOS مع Xcode، أو إعداد EAS لحسابك. تصدير حزم JavaScript لا ينشئ APK أو IPA ولا يثبت نجاح الصوت على جهاز فعلي.

على اللابتوب: `npm run web`. يحتاج التسميع متصفح Chrome أو Edge يدعم Web Speech API، ورابط HTTPS أو localhost، وإذن الميكروفون، وقد يحتاج الإنترنت. دعم العربية وجودة التعرف يعتمدان على مزود نظام الجهاز أو المتصفح. قد يرسل ذلك المزود الصوت إلى خوادمه؛ التطبيق لا يسجل ملفًا ولا يخزّن الصوت أو النص بعد مغادرة الجلسة. يُطلب البدء صراحة داخل القسم، ويُوقف الاستماع عند الخروج منه.

## التحقق والتصدير

```sh
npm test
npm run typecheck
npm run lint
EXPO_NO_TELEMETRY=1 npx expo export --platform ios --platform android --output-dir /tmp/athar-native-export
EXPO_NO_TELEMETRY=1 npx expo export --platform web --output-dir /tmp/athar-web
node scripts/package-web.mjs /tmp/athar-web /tmp/athar-single-file
```

يحوّل الأمر الأخير ملفات JavaScript الخاصة بالواجهة إلى ملف `index.html` واحد مناسب للنشر اليدوي على Netlify، لتفادي رفع الصفحة دون ملفات التفاعل. ارفع المجلد النهائي، ثم اختبر الرابط المنشور؛ المعاينة المحلية لا تثبت نجاح النشر. تستمر الحاجة للإنترنت لتحميل فهرس القراء والصوت وللتعرف الصوتي بحسب الجهاز.

## الميزات وحدودها

- قراءة الفاتحة والإخلاص في شاشة قراءة كاملة، واختيار آية وحفظ موضع القراءة خلال الجلسة. النصوص تحتاج مقابلة ومراجعة علمية قبل النشر.
- **القراء:** جلب القراء والمصاحف والسور المتاحة من `https://mp3quran.net/api/v3/reciters?language=ar` و`https://mp3quran.net/api/v3/suwar`، واختيار الشيخ والرواية والسورة ثم تشغيل السورة كاملة داخل التطبيق، مع الإيقاف والتقديم والرجوع. لا يوجد تنزيل دون اتصال. تحتاج المصادر الخارجية اختبارًا حيًا؛ شبكة بيئة التطوير الحالية تمنع الوصول إليها، واختبارات الدمج تستخدم بيانات وصوتًا تجريبيين صراحة.
- تلاوة الآية داخل مشغل مدمج من EveryAyah بصوت الحصري. تفسير السعدي ما زال رابطًا خارجيًا إلى Quran.com، ولم تُنقل التفاسير إلى قاعدة محلية بعد.
- **التسميع:** استخدام التعرف الصوتي الحقيقي، ثم مطابقة الكلمات المعتمدة بالتتابع مع النص المحلي. يوجد وضع كلمة بكلمة ووضع إظهار الآية بعد اكتمالها. لا تُعتمد النتائج المؤقتة، ولا نتجاوز الكلمات غير المتطابقة. هذه مطابقة نصية أولية وليست تحليلًا صوتيًا متخصصًا أو تقييمًا للتجويد، وقد يصحح مزود التعرف بعض الأخطاء من تلقاء نفسه. يلزم اختبار تلاوات حقيقية وتقييم الدقة؛ الاختبارات الآلية تحاكي أحداث التعرف ولا تثبت دقته على تلاوة بشرية.
- **الفتاوى:** اختيار الشيخ والبحث في فهرس محلي وقراءة السؤال والجواب داخل التطبيق مع المصدر، دون تحويل إجباري إلى المواقع. الفهرس `data/fatwas.json` فارغ حاليًا: لم يتم استيراد أي موقع أو فتوى. الوصول إلى المواقع الرسمية محجوب في البيئة، ولم تُختلق نصوص بديلة أو نتائج توحي بتغطية كاملة.
- بطاقات تعليمية أولية للسورتين؛ أسباب النزول والتاريخ الدقيق غير مدرجين دون توثيق. المساعد الحالي توجيه بالكلمات المفتاحية وليس نموذج ذكاء اصطناعي.

## استيراد الفتاوى

هذه أداة استيراد نصوص تمت مراجعتها وليست زاحفًا لكل المواقع. يلزم توفير المحتوى الأصلي المسموح بإعادة استخدامه والتحقق من نسبته قبل الاستيراد. لا تعيد الأداة صياغة الأجوبة أو تنشئ فتاوى.

```sh
node scripts/import-fatwas.mjs /path/to/reviewed-fatwas.json
```

المدخل مصفوفة، وكل عنصر يحتوي `id`, `scholar`, `title`, `question`, `answer`, `sourceUrl`, `retrievedAt`. أسماء المشايخ المطابقة موجودة في `src/content.ts`، والرابط يجب أن يشير إلى فتوى بعينها في النطاق الرسمي المقابل. `retrievedAt` بتنسيق YYYY-MM-DD. الإجابة نص عادي، ثم يُعاد بناء المعاينة لتضمين الفهرس. التحقق الآلي من البنية والرابط لا يثبت صحة النص؛ المراجعة الأصلية تظل لازمة.

طلب السماح بالنطاقات محفوظ كمسودة: `binbaz.org.sa`, `www.alfawzan.af.org.sa`, `binothaimeen.net`, `mp3quran.net`، مع نطاقات الصوت الفرعية عند تفعيلها. الحفظ لا يطبق الشبكة أو ينشر البيئة. لا توجد مفاتيح خدمات أو بيانات اعتماد مطلوبة للميزات الحالية.

## موقع ثابت يتحدث تلقائيًا

إعداد Netlify موجود في `netlify.toml`: تشغيل `npm run build:web` ونشر مجلد `dist` على Node.js 24. اربط موقع Netlify بمستودع GitHub `osa0mah/App` وفرع `main` مرة واحدة من إعدادات الموقع: Build & deploy → Continuous deployment → Link repository. بعد الربط، تؤدي كل دفعة إلى `main` إلى بناء ونشر النسخة على الرابط نفسه. حفظ الملفات في بيئة التطوير وحده لا ينشرها؛ يلزم commit وpush، ثم اكتمال بناء Netlify. راجع Deploys عند فشل النشر. لا يوجد رمز Netlify أو ربط حساب مُعد في هذه البيئة حاليًا.
