# أثر القرآن

تطبيق عربي أولي للقرآن والتعلم على Android وiOS والويب، مبني باستخدام Expo SDK 58 وReact Native وTypeScript.

## التطوير

```sh
npm ci
npm start
npm run web
```

التسميع يستخدم `expo-speech-recognition`، ويحتاج development build يتضمن الوحدة الأصلية؛ لا يعمل في Expo Go. استخدم `npx expo run:android` مع Android SDK أو `npx expo run:ios` على macOS مع Xcode، أو إعداد EAS لحسابك. على اللابتوب يلزم Chrome أو Edge يدعم Web Speech API، ورابط HTTPS أو localhost، وإذن الميكروفون. قد يرسل المتصفح أو النظام الصوت إلى مزود خدمته؛ التطبيق لا يخزن تسجيلًا. التسميع مطابقة نصية تجريبية وليس تقييمًا للتجويد.

## بناء الموقع والنشر التلقائي

```sh
npm run build:web
```

الأمر يستعيد فهرس العناوين المحفوظ، ويحدّث المصادر التي تحتاج تحديثًا، ثم يصدر واجهة الويب إلى `dist`. إعداد Netlify في `netlify.toml` يحدد أمر البناء، مجلد النشر، وظائف الخادم، وضم ملف `generated/fatwa-catalog.json` إلى الوظائف. المجلد `generated` لا يُرفع إلى Git؛ يُنشأ في كل نشر. لا تنقل فهرسًا فارغًا مولدًا في بيئة محجوبة إلى الإنتاج. يستعيد Netlify النسخة المحفوظة من cache أو النسخة العامة السابقة، ثم يدمج العناوين الجديدة دون حذف السابقة. رفع commit إلى فرع `main` المرتبط بالموقع يطلق البناء والنشر؛ التحقق محليًا لا يثبت نجاح نشر Netlify.

يمكن تشغيل `npm run build:catalog` وحده لتحديث الفهرس في البيئة المحلية التي تصل إلى المصادر. خادم Expo وحده لا يشغّل `/api/chat` أو `/api/fatwas`؛ استعمل Netlify Dev أو الموقع المنشور لاختبار الوظائف. تطبيق الهاتف يستعمل الأصل المحدد في `EXPO_PUBLIC_CONTENT_API_URL` أو موقع المعاينة الافتراضي؛ المتغير رابط عام وليس سرًا.

## فهرس الفتاوى

البحث يعتمد على **عناوين وروابط الصفحات الرسمية المفهرسة**، ولا يعتمد على صفحات البحث في مواقع المشايخ. يجمع البناء البيانات من الروابط والخرائط الرسمية عند توفرها، ويتحقق من النطاق، ويحترم قواعد robots، ويحدد عدد الصفحات والوقت والتزامن. لا تُنسخ أجوبة الفتاوى أثناء الفهرسة، ولا تُستعمل النسخ المتداولة غير المنسوبة أو النصوص المولدة. تُجلب الإجابة من الصفحة الرسمية عند اختيار النتيجة، لذلك قد يتعذر عرض صفحة صوتية فقط أو صفحة تغير تنسيقها.

التغطية **جزئية دائمًا في هذا الإصدار**: حد الفهرسة 60 صفحة لكل مصدر و45 ثانية مشتركة، واتصالان متزامنان لكل مصدر. قد تعطي صفحة واحدة عناوين كثيرة. يظهر عدد العناوين وتاريخ التحديث داخل القسم. لا يوجد تحديث مجدول مستقل؛ المصدر المفهرس حديثًا يُعاد استخدامه 24 ساعة، ومحاولة الجمع الفاشلة تنتظر ساعة قبل إعادة المحاولة في نشر لاحق. لا يثبت غياب عنوان في الفهرس غياب الفتوى من موقع الشيخ.

`GET /api/fatwas?scholar=binbaz&action=status` يعرض جاهزية الفهرس وعدده. البحث يستعمل `action=search&q=...`، وقراءة النص تستعمل `action=read&path=...`. المصادر: `binbaz`, `alfawzan`, `ibnothaimeen`. الفهرس غير المبني أو المصدر الذي لا يملك عناوين يُرجع حالة عدم جاهزية واضحة، ولا يُعرض كبحث ناجح بلا نتائج. يظل تشخيص بنية الصفحة متاحًا عند تعذر استخراج نص فتوى؛ التقرير لا يحتوي HTML كاملًا أو كوكيز أو قيم حقول جلسة.

في بيئة التطوير الحالية، حُجبت المصادر عند جلب robots ولم يُفهرس أي عنوان حي. اختبارات الجمع والبحث تستخدم صفحات تجريبية. يجب فحص أعداد الفهرسة في سجلات بناء Netlify والقسم بعد النشر قبل اعتبار المصادر جاهزة. لم يُثبت بعد نجاح الفهرسة الحية أو القراءة في المواقع الثلاثة.

## الميزات الأخرى

- قراءة الفاتحة والإخلاص بشاشة كاملة واختيار آية وحفظ موضع القراءة خلال الجلسة. النصوص تحتاج مقابلة علمية قبل الإطلاق.
- تفسير السعدي للسورتين مضمّن في `data/tafsir/saadi.json` من Tafsir API v1.2.1، مجموعة QUL رقم 24. النص محفوظ كما ورد ويُعرض داخل التطبيق؛ بيانات المصدر والرخصة مرفقة.
- فهرس القراء والسور يُجلب من MP3Quran، مع تشغيل السورة كاملة داخل التطبيق. تلاوة الآية من EveryAyah. الوصول الحي إلى خدمات الصوت لم يُختبر في هذه البيئة؛ اختبارات الدمج تستخدم بيانات وصوتًا تجريبيين.
- المساعد يعرض الإجابات والمصادر داخل المحادثة، ويتابع سياق السورة والشيخ، ويقدم زر انتقال اختياري. يستخدم نص التفسير أو الفتوى المسترجع، ويصرح بعدم توفر المصدر عند غيابه. المحادثة محفوظة في ذاكرة جلسة التطبيق.

للشرح التوليدي الإضافي، يُضبط مفتاح خادمي سري `ATHAR_AI_API_KEY` في Netlify، وليس في EXPO_PUBLIC أو الكود أو المحادثة. اختياريًا `ATHAR_AI_MODEL`؛ الافتراضي `gpt-4.1-mini`. يُرسل السؤال والنص المسترجع إلى Responses API مع `store:false`، ويظل النص الأصلي منفصلًا عن الشرح. في غياب المفتاح أو تعذر النموذج تبقى الإجابة المسترجعة دون الادعاء بإنشاء شرح توليدي. الاختبار الحي للنموذج لم يُنفذ؛ اختبار البروتوكول يستخدم استجابة محاكاة. استخدام النموذج يخضع لحساب المزود وتكلفته.

## التحقق

```sh
npm test
npm run typecheck
npm run lint
npx expo export --platform ios --platform android --output-dir /tmp/athar-native-export
```

تصدير JavaScript لا ينشئ APK أو IPA ولا يغني عن التجربة على أجهزة فعلية. النشر على المتاجر يحتاج التوقيع والحسابات ومراجعة المحتوى وسياسة الخصوصية. توجد أداة قديمة لاستيراد نصوص تمت مراجعتها `scripts/import-fatwas.mjs`؛ ليست زاحفًا للمواقع ولا بديلًا عن مراجعة الأصل أو فهرس العناوين الخادمي.

طلب `robots.txt` له مهلة 12 ثانية مع محاولة إضافية واحدة فقط للأخطاء المؤقتة ضمن ميزانية البناء، واحترام `Retry-After`. غياب الملف بـ404 أو410 يتيح متابعة الصفحات العامة. تبقى 401 و403 و429، ومشكلات الشهادة، والتحويلات إلى نطاق غير مسجل، أسباب توقف صريحة؛ لا تُعطّل TLS ولا تُغيّر هوية الجلب لتجاوز الرفض. تتضمن حالة المصدر `robots.state`, `robots.code`, `robots.attempts`، ورمز TLS/DNS العام أو نطاق التحويل عند الحاجة، دون تفاصيل الاستثناء أو قيم جلسة. هذه المعلومات تحدد سبب الفشل؛ لا تثبت نجاح الربط بالمصدر الحي قبل إعادة البناء على Netlify.

## منع فقدان الفهرس عند إعادة النشر

سبب التراجع السابق أن كل بناء كان يكتب نتيجة الجمع فوق الفهرس، حتى لو كانت فارغة. الآن تُدمج البيانات السابقة مع الجديدة، وتُكتب الملفات ذريًا بعد التحقق، ويحفظ plugin محلي مجلد `catalog-cache` عبر واجهتي Netlify `utils.cache.restore/save`. توجد نسخة metadata عامة إضافية في `/catalog/fatwas.json` للاستعادة في البناء اللاحق إذا غاب cache. تحتوي النسخة عناوين وروابط رسمية فقط، وتستبعد حقول الأجوبة والحقول غير المتوقعة. لا تُرسل إليها بيانات محادثة أو أسرار. الملفات المولدة لا تُرفع إلى Git.

في بناء Netlify، تُرفض نتيجة أقل من **277 عنوانًا لابن باز**، وهو آخر عدد ثبت عمله عند المستخدم. توقف البناء في هذه الحالة مقصود لمنع استبدال النشر الحالي بفهرس أصغر؛ لا يعني أن البيانات القديمة استُعيدت تلقائيًا. تتطلب أول عملية حفظ نسخة ناجحة من المصدر أو نسخة احتياطية موجودة. الحماية لا تسترجع بيانات فُقدت قبل وجود backup، وقد يلزم الرجوع إلى آخر نشر ناجح من لوحة Netlify.

إذا فشل تحديث مصدر وله بيانات محفوظة، يبقى البحث فيها متاحًا ويظهر تنبيه، ويحافظ تاريخ البيانات على وقته السابق مع فصل `lastAttemptAt`. يمكن طلب تحديث صريح في البناء بواسطة `FATWA_REFRESH_CATALOG=true`؛ هذا لا يتجاوز حد منع فقدان البيانات. إذا أُعيدت تسمية الموقع، يحتاج عنوان استعادة snapshot العام في `server/catalogSnapshot.mjs` إلى تحديث مُراجع؛ يقبل حاليًا نطاق المشروع المعروف فقط ويمنع التحويلات. نجاح اختبارات محاكاة cache لا يثبت حفظه على Netlify؛ يُتحقق من ذلك في البناء المنشور.

مهلة اتصال صفحات المصدر وملف robots.txt هي 12 ثانية لكل طلب ضمن ميزانية الجمع العامة. يحتوي status على `pageFailures` (حتى ثلاثة مسارات ورموز اتصال فقط)، دون رسائل الأخطاء الخام أو معاملات البحث، لتحديد فشل الصفحات بدل اعتباره انعدام نتائج.

قراءة صفحات المصدر وخرائط المواقع تسمح الآن حتى 16 MiB من البيانات المفكوكة عبر stream، بدل حد مليوني حرف السابق؛ يبقى robots.txt محدودًا بـ1 MiB. تلغي القراءة الاستجابة بمجرد تجاوز الحد قبل تحليل HTML/XML. يحفظ الفهرس `bodyLimitBytes` لإعادة محاولة المصادر التي فشلت بحد الحجم القديم فور أول بناء بهذا التعديل، ثم يستعيد فترة التهدئة المعتادة إذا استمر الفشل. لا يغيّر هذا التعديل التحقق من شهادات TLS.

موقع ابن عثيمين الحالي يستخدم مسارات `/ar/voice_library/lessonDetails/<section>/<title>/<UUID>`، وليس `/content/<number>` فقط. يستخرج المفهرس عناوين URL المنشورة في خريطة الموقع الرسمية ويزيل تكرار UUID، دون تقييم JavaScript أو تخزين أجوبة الفتاوى. خرائط XML محدودة بـ32 MiB وتُقرأ عناصر loc دون إنشاء DOM كامل؛ صفحات HTML تبقى محدودة بـ16 MiB. عند فتح نتيجة جديدة، تُقرأ حقول `title.ar` و`objective.content.ar` من واجهة الموقع العامة الثابتة `shekhapi.binothaimeen.net/lessons/audios/show/...` التي تستخدمها واجهته الرسمية، مع مطابقة UUID ورفض التحويلات والنص المفقود. لا تسمح مسارات القراءة للمستخدم بتحديد مضيف API.

فحص حي في 2026-11-05: جرى تحميل خريطة ابن عثيمين (16,916,038 بايت)، وفهرسة 16,781 عنوانًا محليًا، والبحث عن الصلاة وقراءة نص نتيجة فعلية عبر الواجهة الرسمية. هذه عناوين مواد صوتية منشورة؛ قد تضم دروسًا، وبعض المواد لا تملك تفريغًا نصيًا. لا يعني هذا التحقق نجاح نشر Netlify. أعاد نطاقا الفوزان الرسميان حين الفحص HTTP 503 من وسيط الاتصال مع `CERTIFICATE_VERIFY_FAILED`؛ لم تُعطّل مراجعة TLS. موقع Netlify نفسه يعرض Login Redirect للفحص الخارجي في البيئة الحالية.

التسميع يبدأ بزر واحد دون اختيار كلمة/آية. تبقى الآية كاملة مخفية حتى مطابقة كلماتها كلها بالترتيب؛ المقطع الخاطئ لا يُكتب للمستخدم. تُحفظ بداية الآية المطابقة بين نتائج الصوت النهائية، وتُهمل عند مخالفتها، مع قبول إعادة الآية الصحيحة. يستمر الاستماع ويُستأنف بعد نهاية جلسة عادية من المحرك، ويتوقف عند الإيقاف أو مغادرة الشاشة أو اكتمال السورة أو خطأ صلاحيات/خدمة؛ توجد حماية من حلقات إعادة التشغيل السريعة. اجتاز مثال الإخلاص واختبارات دورة الجلسة في Chromium بنتائج صوت محاكاة؛ لم يُختبر صوت بشري فعلي في بيئة التطوير.

جلسة الميكروفون على الويب تُفتح بواسطة getUserMedia وتظل مفتوحة أثناء إعادة اتصال خدمة SpeechRecognition؛ لا يوجد MediaRecorder ولا حفظ للتسجيل. انقطاع الشبكة يعيد المحاولة بتأخير متزايد حتى 15 ثانية دون إنهاء الجلسة، ويعرض تعذّر الاتصال بدل الادعاء بأن المطابقة تعمل. الإيقاف واكتمال السورة ومغادرة الشاشة والخطأ الدائم يغلقون مسارات الميكروفون. دعم واجهة SpeechRecognition وحده لا يضمن وجود خدمة صوت فعالة في Brave؛ تُقترح تجربة Chrome/Edge عند تعذّر الخدمة. الاختبارات بمحاكاة نتائج الصوت ومسارات الميكروفون، وليست تحققًا من خدمة المتصفح الحية.

لتقليل تأخير العرض، التسميع يستخدم الآن `interimResults: true`: تظهر الآية الكاملة المطابقة فور وصول فرضية التعرّف الأولية، وتُحسب كل فرضية انطلاقًا من آخر تقدم نهائي دون تجميع النتائج الأولية المتكررة. إذا راجع المحرك فرضيته يُصحح العرض، ولا يُغلق الميكروفون أو تُعلن نهاية السورة إلا بتأكيد النتيجة النهائية. اجتاز اختبار المتصفح ظهور الآية قبل final، وتصحيح الفرضية، وبقاء زر الإيقاف فعّالًا عند عرض السورة كاملة مبدئيًا. لا يضمن ذلك زمن استجابة خدمة المتصفح نفسها.

يمكن اختيار «كلمة بكلمة» أو «الآية كاملة» (الافتراضي) في شاشة التسميع. وضع الكلمات يطابق الكلمات بالتتابع ويقف عند أول اختلاف، ويقبل إعادة المقطع دون مضاعفة التقدم، مع عرض النتائج الأولية سريعًا واعتماد النتائج النهائية فقط كتقدم ثابت. لا تُكشف الكلمات التالية عند نطق آية متأخرة. تغيير النمط يوقف الجلسة ويعيد التقدم من البداية. نجحت اختبارات المطابقة واختبار المتصفح بمحاكاة الصوت لكلا النمطين، والتصحيح والتكرار والإكمال واستمرار جلسة الميكروفون.

للتفريق بين تأخر خدمة التعرّف والخطأ في القراءة، تعرض شاشة التسميع مؤشر وصول صوت محليًا قبل وصول النص من Chrome. على الويب يقرأ Web Audio مستوى الإشارة كل 80ms، دون تسجيل أو تشغيل الصوت عبر السماعات أو إرساله إلى خدمة إضافية؛ مهلة الصمت 4 عينات لمنع الوميض. يتوقف التحليل ويُغلق AudioContext عند إغلاق الميكروفون. هذا مؤشر وجود إشارة صوتية، وليس حكمًا على صحة القراءة ولا تسريعًا مضمونًا لخدمة SpeechRecognition. يبقى إظهار الكلمات مشروطًا بالنص المطابق؛ اختبارات المتصفح تستخدم إشارة صوت ونتائج تعرّف محاكاة.
