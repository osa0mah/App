# أثر القرآن

تطبيق عربي أولي للقرآن والتعلم على Android وiOS والويب، مبني باستخدام Expo SDK 58 وReact Native وTypeScript.

## التطوير

```sh
npm ci
npm start
npm run web
```

التسميع يستخدم `expo-speech-recognition`، ويحتاج development build يتضمن الوحدة الأصلية؛ لا يعمل في Expo Go. استخدم `npx expo run:android` مع Android SDK أو `npx expo run:ios` على macOS مع Xcode، أو إعداد EAS لحسابك. على اللابتوب يلزم Chrome أو Edge يدعم Web Speech API، ورابط HTTPS أو localhost، وإذن الميكروفون. قد يرسل المتصفح أو النظام الصوت إلى مزود خدمته؛ التطبيق لا يخزن تسجيلًا. التسميع مطابقة نصية تجريبية وليس تقييمًا للتجويد.

## بناء الموقع والنشر التلقائي

```sh
npm run build:web
```

الأمر يبني فهرس العناوين أولًا ثم يصدر واجهة الويب إلى `dist`. إعداد Netlify في `netlify.toml` يحدد أمر البناء، مجلد النشر، وظائف الخادم، وضم ملف `generated/fatwa-catalog.json` إلى الوظائف. المجلد `generated` لا يُرفع إلى Git؛ يُنشأ في كل نشر. لا تنقل ملفًا مولدًا من بيئة محجوبة إلى الإنتاج؛ Netlify يعيد توليده من المصادر نفسها. رفع commit إلى فرع `main` المرتبط بالموقع يطلق البناء والنشر؛ التحقق محليًا لا يثبت نجاح نشر Netlify.

يمكن تشغيل `npm run build:catalog` وحده لتحديث الفهرس في البيئة المحلية التي تصل إلى المصادر. خادم Expo وحده لا يشغّل `/api/chat` أو `/api/fatwas`؛ استعمل Netlify Dev أو الموقع المنشور لاختبار الوظائف. تطبيق الهاتف يستعمل الأصل المحدد في `EXPO_PUBLIC_CONTENT_API_URL` أو موقع المعاينة الافتراضي؛ المتغير رابط عام وليس سرًا.

## فهرس الفتاوى

البحث يعتمد على **عناوين وروابط الصفحات الرسمية المفهرسة**، ولا يعتمد على صفحات البحث في مواقع المشايخ. يجمع البناء البيانات من الروابط والخرائط الرسمية عند توفرها، ويتحقق من النطاق، ويحترم قواعد robots، ويحدد عدد الصفحات والوقت والتزامن. لا تُنسخ أجوبة الفتاوى أثناء الفهرسة، ولا تُستعمل النسخ المتداولة غير المنسوبة أو النصوص المولدة. تُجلب الإجابة من الصفحة الرسمية عند اختيار النتيجة، لذلك قد يتعذر عرض صفحة صوتية فقط أو صفحة تغير تنسيقها.

التغطية **جزئية دائمًا في هذا الإصدار**: حد الفهرسة 60 صفحة لكل مصدر و45 ثانية مشتركة، واتصالان متزامنان لكل مصدر. قد تعطي صفحة واحدة عناوين كثيرة. يظهر عدد العناوين وتاريخ التحديث داخل القسم. لا يوجد تحديث مجدول مستقل؛ يُعاد الجمع مع كل نشر. لا يثبت غياب عنوان في الفهرس غياب الفتوى من موقع الشيخ.

`GET /api/fatwas?scholar=binbaz&action=status` يعرض جاهزية الفهرس وعدده. البحث يستعمل `action=search&q=...`، وقراءة النص تستعمل `action=read&path=...`. المصادر: `binbaz`, `alfawzan`, `ibnothaimeen`. الفهرس غير المبني أو المصدر الذي لا يملك عناوين يُرجع حالة عدم جاهزية واضحة، ولا يُعرض كبحث ناجح بلا نتائج. يظل تشخيص بنية الصفحة متاحًا عند تعذر استخراج نص فتوى؛ التقرير لا يحتوي HTML كاملًا أو كوكيز أو قيم حقول جلسة.

في بيئة التطوير الحالية، حُجبت المصادر عند جلب robots ولم يُفهرس أي عنوان حي. اختبارات الجمع والبحث تستخدم صفحات تجريبية. يجب فحص أعداد الفهرسة في سجلات بناء Netlify والقسم بعد النشر قبل اعتبار المصادر جاهزة. لم يُثبت بعد نجاح الفهرسة الحية أو القراءة في المواقع الثلاثة.

## الميزات الأخرى

- قراءة الفاتحة والإخلاص بشاشة كاملة واختيار آية وحفظ موضع القراءة خلال الجلسة. النصوص تحتاج مقابلة علمية قبل الإطلاق.
- تفسير السعدي للسورتين مضمّن في `data/tafsir/saadi.json` من Tafsir API v1.2.1، مجموعة QUL رقم 24. النص محفوظ كما ورد ويُعرض داخل التطبيق؛ بيانات المصدر والرخصة مرفقة.
- فهرس القراء والسور يُجلب من MP3Quran، مع تشغيل السورة كاملة داخل التطبيق. تلاوة الآية من EveryAyah. الوصول الحي إلى خدمات الصوت لم يُختبر في هذه البيئة؛ اختبارات الدمج تستخدم بيانات وصوتًا تجريبيين.
- المساعد يعرض الإجابات والمصادر داخل المحادثة، ويتابع سياق السورة والشيخ، ويقدم زر انتقال اختياري. يستخدم نص التفسير أو الفتوى المسترجع، ويصرح بعدم توفر المصدر عند غيابه. المحادثة محفوظة في ذاكرة جلسة التطبيق.

للشرح التوليدي الإضافي، يُضبط مفتاح خادمي سري `ATHAR_AI_API_KEY` في Netlify، وليس في EXPO_PUBLIC أو الكود أو المحادثة. اختياريًا `ATHAR_AI_MODEL`؛ الافتراضي `gpt-4.1-mini`. يُرسل السؤال والنص المسترجع إلى Responses API مع `store:false`، ويظل النص الأصلي منفصلًا عن الشرح. في غياب المفتاح أو تعذر النموذج تبقى الإجابة المسترجعة دون الادعاء بإنشاء شرح توليدي. الاختبار الحي للنموذج لم يُنفذ؛ اختبار البروتوكول يستخدم استجابة محاكاة. استخدام النموذج يخضع لحساب المزود وتكلفته.

## التحقق

```sh
npm test
npm run typecheck
npm run lint
npx expo export --platform ios --platform android --output-dir /tmp/athar-native-export
```

تصدير JavaScript لا ينشئ APK أو IPA ولا يغني عن التجربة على أجهزة فعلية. النشر على المتاجر يحتاج التوقيع والحسابات ومراجعة المحتوى وسياسة الخصوصية. توجد أداة قديمة لاستيراد نصوص تمت مراجعتها `scripts/import-fatwas.mjs`؛ ليست زاحفًا للمواقع ولا بديلًا عن مراجعة الأصل أو فهرس العناوين الخادمي.
